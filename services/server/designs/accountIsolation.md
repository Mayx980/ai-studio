# 服务端用户隔离候选

本设计服务于 Issue #7 独立账号修订，尚未实现，需与 [Plan](../../../.wf-prod/plans/issue-7/plan.md) 一并确认。系统与数据规则分别见 [architecture](../../../architecture/architecture.md)、[accounts](../../../contracts/data/accounts.md)。遵循项目 AGENTS 的 Bun/Express、统一文件入口和单进程边界，不引入服务框架或认证数据库。

## 配置、路径与异步归属

保留 `utils/conf/index.ts` 中实例配置单例，用于可信系统插件及宿主设置。用户配置也只在该模块按用户 ID 建立并缓存，不能每次请求创建 conf；用户的 `settings.json` 继续权限 `0o600`、完整覆盖普通设置及保留/更新/清除 Key。普通用户保存配置只能写个人字段，不能连带修改实例插件、MCP 监听或宿主参数。

新增 `utils/accounts/` 承担真实账号持久化、会话验证和当前身份；通过 `utils.ts` 暴露业务入口。复用 `lib/i18n.ts` 已采用的 AsyncLocalStorage 方式，在认证后携带不可变用户 ID、数据根、会话身份；HTTP body 和查询参数不产生身份。缺失上下文必须拒绝用户数据访问，不能回退实例或管理员。只读实例资源通过明确的系统入口访问。

逐个核对所有 `conf.get/set/onDidChange`、`dirname(conf.path)` 及等价目录拼接：项目/个人资料改取用户配置与固定根，可信代码安装与运行资源继续取实例根。供应商定义代码可共享，已启用模型、Key、余额、价格及初始化缓存按用户和配置版本区分。配置刷新只影响该用户，不把某个请求的设置写入全局供应商状态。

工作区、资产和模板继续复用原路径解析、realpath 与符号链接保护、业务锁、writeAtomic、exclusive、expectedRevision。初始管理员的旧根仅允许其原 workspaces/assets/templates 等业务子目录；不能因为管理员旧根在实例根就允许读取 accounts.json、users 或 settings 凭据文件。路径、跨项目引用、下载及复制在服务端逐项授权。

Agent 会话、singleAgent 会话、question/canvas bridge、事件流和任务 handle 均绑定 owner；查询、回复、停止、重连必须检查 owner，不能只凭不可猜的 ID。任务开始时捕获用户和目录，异步结果固定写回该用户原项目；切换 UI、其它账号登录或全局设置变化不改变归属。退出、停用/重置、过期会话关闭其事件订阅并拒绝新操作；已被供应商接受的任务不承诺撤销，已有结果只保存到原 owner。本版仍不支持 Server 重启后的任务恢复。

## 账号写入及安全入口

账号/会话共用一个原子记录，使新建、重名保护、登出、密码版本变更有同一协调边界；密码哈希在锁外异步计算，提交时重验用户版本，避免持锁计算和过期改密覆盖。初始化采用 exclusive，失败不生成可登录的半成品；通过容器本地命令安全输入用户名与密码，命令参数、日志和 Compose 不写真实密码。新增脚本须进入聚合构建输出。

最小账号管理仅含创建普通账号、启停、重置密码及本人改密；不新增删除/任意角色授权。最后一个有效管理员受保护。登录失败限速、输入大小、哈希并发及会话过期清理均是运行时业务校验，不建立自检脚本。

认证中间件覆盖业务 API；路由按认证公开入口、个人业务、可信管理员操作、禁止的未绑定旁路逐项核对，未分类能力默认拒绝。普通用户禁止服务端插件/团队/技能/Provider 源码安装、编辑、调试、任意脚本和宿主控制。已安装的可信工具可用于本人项目，但不能提供任意绝对文件系统读写来绕过用户根；逐项核对 workspace/asset/browser/media 等工具的宿主能力和本地浏览器状态。

独立 Server 的多用户模式不启动未绑定用户的外部 MCP/A2A/设备互联监听，不接受旧 token 访问多用户数据；普通 Web 中的 Agent/画布内部桥接仍按会话用户工作。原生本机模式通过 `createApp` 的受控启动参数保留既有路径，不允许由 HTTP 请求选择绕过认证。原生客户端连接多用户 Server 也必须登录；本版不承诺完成所有原生平台联调。

## 新增结构的理由与限制

账号记录、Session 和 AsyncLocalStorage 是独立身份与跨异步授权所必需；现有演示 Store、全局 conf 或前端目录过滤均不构成服务端认证。继续复用文件原语、conf、已有路由生成、响应和密码平台能力，不引入 controller/repository 层、第二套文件封装、JWT 或新 ORM。

原子 JSON 适用于当前内部单进程部署，会话增多时整个记录读写成本增加；不支持多进程同时写同一卷。规模或多副本需求出现时迁移身份存储和锁模型，不能靠删除冲突保护或开启多个 worker 扩容。可信部署管理员及其可执行插件拥有服务器权限，业务隔离不宣称能防御已被授权的服务器任意代码执行。

实际改动需覆盖本设计所有消费方，并用双用户 HTTP/浏览器及重启验证；当前只记录方案，具体实施位置和验证顺序见 Tasks。
