# 服务端用户隔离设计

本设计服务于 Issue #7 独立账号修订，已接入源码，真实环境未联调，需与 [Plan](../../../.wf-prod/plans/issue-7/plan.md) 一并确认。系统与数据规则分别见 [architecture](../../../architecture/architecture.md)、[accounts](../../../contracts/data/accounts.md)。遵循项目 AGENTS 的 Bun/Express、统一文件入口和单进程边界，不引入服务框架；本轮按人工要求增加 MySQL，数据事务见 [database](../../../contracts/data/database.md)。

## 配置、路径与异步归属

保留 `utils/conf/index.ts` 的实例配置单例，用于可信系统插件及宿主设置；个人配置改由数据库读取，不再为每个用户建立 conf/settings.json。认证后异步载入当前用户和配置版本，放入请求上下文给现有同步消费者读取；保存采用 SQL 事务，保留普通设置完整覆盖和 Key 的保留/更新/清除语义，按用户/版本刷新缓存。普通用户不能连带修改实例插件、MCP 监听或宿主参数。

新增 `utils/database/` 持有唯一应用 SQL 连接池和所属业务事务入口，`utils/accounts/` 承担账号/Session 的数据库操作、认证和当前身份；均通过 `utils.ts` 暴露业务入口，不再封装一套文件原语。SQL 客户端沿用 Bun 内置能力，初始化在稳定启动位置完成，不每请求新建连接池，不让应用请求执行 DDL。复用 `lib/i18n.ts` 已采用的 AsyncLocalStorage 方式，在认证后携带不可变用户 ID、数据根、会话身份；HTTP body 和查询参数不产生身份。缺失上下文必须拒绝用户数据访问，不能回退实例或管理员。只读实例资源通过明确的系统入口访问。

逐个核对所有 `conf.get/set/onDidChange`、`dirname(conf.path)` 及等价目录拼接：项目/个人资料改取用户数据库设置与固定文件根，可信代码安装与运行资源继续取实例根。供应商定义代码可共享，已启用模型、Key、余额、价格及初始化缓存按用户和配置版本区分。配置刷新只影响该用户，不把某个请求的设置写入全局供应商状态。

工作区、资产和模板继续复用原路径解析、realpath 与符号链接保护、业务锁、writeAtomic、exclusive、expectedRevision。初始管理员的旧根仅允许其原 workspaces/assets/templates 等业务子目录；不能因为管理员旧根在实例根就允许读取账号配置、其它 users 根或 settings 凭据文件。路径、跨项目引用、下载及复制在服务端逐项授权。

Agent 会话、singleAgent 会话、question/canvas bridge、事件流和任务 handle 均绑定 owner；查询、回复、停止、重连必须检查 owner，不能只凭不可猜的 ID。任务开始时捕获用户和目录，异步结果固定写回该用户原项目；切换 UI、其它账号登录或全局设置变化不改变归属。退出、停用/重置、过期会话关闭其事件订阅并拒绝新操作；已被供应商接受的任务不承诺撤销，已有结果只保存到原 owner。本版仍不支持 Server 重启后的任务恢复。

## 账号写入及安全入口

账号/Session 通过 InnoDB 事务、用户名/会话摘要唯一约束及认证版本条件协调；密码哈希在事务外异步计算，提交时重验版本。schema 初始化/演进由同版本运维包负责；容器本地 createAdmin 入口只在已核对 schema 上建立首个管理员并显式接管旧索引/配置，事务失败不发布半完成身份。用户名密码在受控终端安全输入，不写参数/日志/Compose；新增入口进入聚合构建输出。

最小账号管理仅含创建普通账号、启停、重置密码及本人改密；不新增删除/任意角色授权。最后一个有效管理员受保护。登录失败限速、输入大小、哈希并发及会话过期清理均是运行时业务校验，不建立自检脚本。

认证中间件在任何业务加载前验证数据库 Session、账号状态及页面身份；DB 不可用/缺结构返回 503，不当成未注册、匿名或回退 JSON。认证覆盖业务 API；路由按认证公开入口、个人业务、可信管理员操作、禁止的未绑定旁路逐项核对，未分类能力默认拒绝。普通用户禁止服务端插件/团队/技能/Provider 源码安装、编辑、调试、任意脚本和宿主控制。已安装的可信工具可用于本人项目，但不能提供任意绝对文件系统读写来绕过用户根；逐项核对 workspace/asset/browser/media 等工具的宿主能力和本地浏览器状态。

独立 Server 的多用户模式不启动未绑定用户的外部 MCP/A2A/设备互联监听，不接受旧 token 访问多用户数据；普通 Web 中的 Agent/画布内部桥接仍按会话用户工作。原生本机模式通过 `createApp` 的受控启动参数保留既有路径，不允许由 HTTP 请求选择绕过认证。原生客户端连接多用户 Server 也必须登录；本版不承诺完成所有原生平台联调。

## 新增结构的理由与限制

账号记录、Session 和 AsyncLocalStorage 是独立身份与跨异步授权所必需；现有演示 Store、全局 conf 或前端目录过滤均不构成服务端认证。继续复用文件原语、系统 conf、已有路由生成、响应和密码平台能力；数据库只承担本次明确需要的持久元数据与事务，不引入 controller/repository 层、JWT、第二套文件封装或 ORM。

独立数据库满足本轮明确要求，账号/索引从整份 JSON 锁切到用户记录及事务约束；SQL 不消除工作区文件锁、外部 SDK、浏览器自动化上下文和任务的进程内状态，首版仍单实例。全部 SDK/工具状态也须按 owner 分离或禁止相应旁路，不能仅改 DB 查询便宣称支持多副本。可信部署管理员及其可执行插件拥有服务器权限，业务隔离不宣称能防御已被授权的服务器任意代码执行。

实际改动需覆盖本设计所有消费方，并用双用户 HTTP/浏览器及重启验证；当前只记录方案，具体实施位置和验证顺序见 Tasks。

用户模型 Key 按数据库合同加密入库，连接及根加密密钥从受限 secret 文件取得；缺密钥必须停止读取，不自动换钥或覆盖旧密文。旧 JSON 接管成功后只作来源备份，所有运行元数据从数据库读取，不双写。文件写入与 SQL 发布分两步，补偿只处理本次独占未发布对象，失败不删已有资料。

## 公司HTTP媒体存储修订设计

在现有 `utils/` 下拟新增 `mediaStorage/`，用Bun原生fetch/FormData消费 [mediaStorage](../../../contracts/data/mediaStorage.md)；只统一媒体内容读写，不全局替换文件原语、不引入Go服务或gRPC依赖。配置启动时从文件/环境读取，普通用户不能改服务地址或bucket。

现有工作区/资产逻辑入口解析当前用户、逻辑路径与SQL媒体记录：新oss内容走HTTP，旧local记录保留统一文件入口和realpath边界；云端失败不能改走本地。生成结果、参考读取、图片编辑、音视频/FFmpeg、Agent文件工具、历史、个人资产及项目/模板复制的等价读写都需纳入影响核对，禁止只替换页面上传。FFmpeg和SDK实际需要文件时，仅物化受限临时文件，捕获原用户/项目，完成或失败后按明确边界清理，不建立第二份持久内容来源。

媒体读取在服务端授权后代理，保留Range、正确MIME、取消和资源释放；部分上游200 JSON错误不能作为成功媒体处理。独占新对象先上传，SQL事务成功后发布；物理删除及签名能力不能由同名Go方法推断。当前没有云端联调或实现证据，完整消费者核对、缺失能力与失败验证纳入本轮Tasks。

当前实现使用 `utils/accounts` 的请求上下文、真实Cookie与会话撤销，实例conf单例在多用户请求内读写SQL个人配置，缺上下文不回退管理员。媒体任务捕获服务端上下文，以原owner和目录保存；页面身份不一致拒绝、长连接失权关闭。多用户FFmpeg使用受控参数及临时文件，模型出站使用运维允许base，避免普通配置绕过无鉴权OSS。部署管理员及其安装的代码仍是可信主体。
