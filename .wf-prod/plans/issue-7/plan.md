## 服务端实现方案

### 持久化与接口

- 复用 `createApp` 在路由加载前设置的 `TOONFLOW_DATA_DIR`、单进程配置实例及 `data/workspaces/`、`data/assets/`。继续使用 `@toonflow/file`、`writeAtomic`、exclusive 创建、既有按路径协调队列与业务冲突锁，不引入数据库或额外服务。
- 前端工作区文件统一走 `useWorkspaceFiles`；目录由服务端规范化并限制在允许根内，文件参数保持工作区相对路径。不能将 `browser://...` 当作系统路径，也不能通过放宽现有工作区授权来访问全局资产或模板目录。
- 项目名称、目录登记、封面引用、生成历史、标签和模板索引成为服务端事实。可正确承载的部分复用现有设置/Store 通道；涉及独立冲突控制的业务索引在所属模块维护有版本的 JSON 快照，不能被过期的整份页面设置静默覆盖。前端本地只保存当前视图、选中项、首次提示等非业务状态或偏好。
- 项目创建先完成目录及初始文件写入，再发布列表项；失败仅处理本次未完成对象。复制保持文件独立；移除项目列表项继续保留项目文件。资产与模板全局操作复用各自业务入口，不重复封装工作区 HTTP 请求。
- 服务端会话沿用现有 `.agent` 会话保存能力，必要创作状态随所属会话保存；不能仅保存消息文本而丢失专业创作阶段、参考和已采用结果。另一个浏览器打开同实例可恢复保存内容；同时编辑的旧 revision 明确冲突，不覆盖新版本。
- 沿用 `validateFields`、Zod、`success/error` 和统一错误处理；一个接口一个文件，工具放 `utils` 并通过 `u` 暴露。路由新增或变更后运行现有 routes 生成器，不手改 `router.ts`。

### 模型、凭据与请求生命周期

- 浏览器只向现有 Server 请求模型、文本和媒体生成，不依赖 Vite `studioRelay`，不把本机开发代理改造成任意 URL 代理。原型中已确认的文本/图片/视频/音频协议，先核对服务端已有实现，缺口在现有 `packages/providers` 与 AI/media 业务边界补齐。
- 本版方案采用实例级服务端模型配置：凭据由 Server 保存并用于供应商请求，复用既有 `settings.json`、`configFileMode: 0o600` 和初始化目录。Key 不进入画布、会话、模板、生成历史、日志或前端本地存储；通用读取响应返回配置状态和必要模型元数据，不能把原始 Key 随整份设置回传。
- 凭据的保存、保持原值和显式清除先形成精确合同，再调整对应调用方。其它设置仍保持完整覆盖语义，不能因返回脱敏数据而在下一次保存时清空凭据，也不能无需求把所有设置改为部分合并。此处已获确认，替代原型“刷新清除内存 Key”的使用方式，本轮按此合同落地。
- 未配置或被禁用的模型明确不可用，禁止回退未授权供应商。参考与参数按实际能力校验，上传/连线/参数修改不触发生成；媒体在服务端下载并保存成功后才返回可用文件引用。
- 应用内切换项目或画布仍需继续已提交任务，结果固定到原项目/画布/节点；复用现有请求和公共生成生命周期，不以 UI 卸载直接取消。浏览器关闭或 Server 重启后的持续执行/恢复不在本轮承诺内，不新增持久任务队列；明确停止及删除节点的取消行为单独保留。

### 兼容与运行

- 保留既有服务端 `data/`、配置名称、项目文件及节点格式、revision/连线 identity 和插件公开导出。浏览器原型存储不自动导入 Server；迁移如被另行要求，先明确来源、范围与冲突处理。
- 正式启动使用现有 Web+Server 开发入口；构建后由 Server 的 `webRoot` 提供同源页面与 API。验证普通开发入口和构建启动，不以仅 studio 模式可运行作为交付。
- 不用演示账号制造鉴权或个人资产隔离的表象；共享工作区的访问者拥有相同业务边界。部署仍遵循现有受控访问约定，生产发布属于独立入口，本轮不执行。
