# 公司 HTTP 云存储运行候选

本页尚未实现；当前镜像和 Compose 没有这些配置项。候选复用已存在的公司 storage HTTP 服务，不再部署另一套 OSS 或 Go 网关。外部协议、用户授权、删除缺口和兼容规则唯一维护在 [mediaStorage](../contracts/data/mediaStorage.md)；MySQL/密钥运行见 [database](database.md)。

## 配置来源

用户明确选择服务地址与 bucket 后填。实施时支持一个可选 JSON 配置文件，并允许 Docker Compose 环境变量覆盖；环境变量优先于配置文件。显式空环境变量视为缺失并报错，不静默沿用旧值。以下名称是本版拟实现配置，尚不能给现有镜像配置后就宣称生效：

| 环境变量 | 配置文件字段 | 含义 |
| --- | --- | --- |
| `AFXEN_STORAGE_CONFIG` | 无 | 可选配置文件绝对路径；用统一文件入口读取，文件须为 JSON 对象 |
| `AFXEN_STORAGE_BASE_URL` | `baseUrl` | HTTP/HTTPS 服务根地址，可含明确网关前缀；不含用户密码、query 或 fragment |
| `AFXEN_STORAGE_BUCKET` | `bucket` | 实际桶名，单路径段，不含分隔符或控制字符 |
| `AFXEN_STORAGE_PREFIX` | `prefix` | 实例隔离前缀；缺省 `afxen`，不含 `..`、空段或控制字符 |

地址和 bucket 不提供猜测的默认值；地址只由部署人员配置，不能由普通浏览器请求修改。提供配置文件路径却无法读取/解析时明确失败，不把该错误忽略后继续；环境变量不需要填写虚构 Token，HTTP边界不发送任何模型凭据。实际超时、并发和响应上限在现有100 MiB媒体上限内于实现中明确，不以空配置导致无限等待。

配置未齐时云上传/读取能力明确不可用，保留输入和旧本地资料；不得声称上传成功、自动创建默认bucket、偷偷写回本地或触发供应商生成后才发现无法存储。部署启用云媒体前健康/能力检查核对配置，健康检测本身不发起上传或删除请求；外部连通性与真实保存需人工另行验证。

## 网络与媒体访问

后端需能访问配置的 HTTP 服务；浏览器访问 AFXEN 自己的媒体入口。当前 OSS 无鉴权，部署侧须限制其可达范围；本页不更改现有 APISIX 路由，也不把它发布为对所有用户开放的文件接口。用户能直接访问 OSS 时，应用内用户隔离不能保护该旁路，目标机必须如实核实此条件。

原生本机文件模式和旧数据卷保留；新云对象与SQL媒体记录共同保存，画布/对话/模板JSON仍在原卷。Compose保留应用端口、appData及候选mysqlData，不给媒体目录做无关搬迁，不新增Go容器。对象读取不依赖过期签名URL，URL不作为持久索引。

## 备份、删除与恢复

云媒体启用后的完整恢复材料为：同一时点数据库、仍在本地的业务文件卷、模型凭据根密钥，以及所用bucket/prefix中的云对象及其保留策略。数据库备份不能代替媒体备份；保存bucket名称也不等于对象已备份。具体云端备份能力由公司storage运维确认，本轮不修改其云厂商配置。

当前HTTP没有物理删除接口。候选仅逻辑解除本用户关联、保留实际对象，需随计划确认；不执行伪造DELETE，不把SQL回滚或移除卡片写成对象已清理。上传成功但SQL失败的未发布对象需保留待处理位置，不能静默堆积或无依据删除已有对象。后续清理须具备真实删除协议、引用核对、对象清单和目标授权。

旧媒体迁移、真实OSS联调、目标机发布与恢复不因保存本方案而获授权；配置由部署人员后填，验证结果与构建结果分别交接。
