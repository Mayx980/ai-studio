# 媒体云存储接入候选

本页是 Issue #7 的待审协议，尚未实现。只调整图片、视频、音频及其缩略图的持久化落点；复用现有 Bun Server、页面 Port、工作区与资产入口，不新增 Go 服务。画布、对话和模板的 JSON 正文在本轮仍沿用文件格式；此前讨论的画布/对话入库建议不作为已确认范围。账号与 SQL 设计分别见 [accounts](accounts.md)、[database](database.md)，部署配置见 [storage](../../ops/storage.md)。

## 已核实的外部协议

HTTP 来源是公司 [storage@16d1c58d](https://git.aimall-tech.com/product/infra/storage/-/blob/16d1c58d92e1c7773dd90f5bb1e85475e7c7f0b0/docs/API.md) 及其 [真实路由](https://git.aimall-tech.com/product/infra/storage/-/blob/16d1c58d92e1c7773dd90f5bb1e85475e7c7f0b0/app/internal/api/http_router.go)。用户提供的 Go 封装及 [infra API@222bc8cb](https://git.aimall-tech.com/product/infra/api/-/blob/222bc8cbea79a137cd7230be561c64125837633f/pb/oss/v1/kit_pb_oss.proto) 只作业务方法与 gRPC 能力参考，不反向创造 HTTP endpoint。

| 能力 | 当前 HTTP 契约 | 接入要求 |
| --- | --- | --- |
| 保存媒体 | `POST /{bucket}/{object}`；multipart 的文件字段为 `file`；成功为 200、空响应体 | 后端使用 FormData，由运行时生成 boundary；不把文件编码成猜测的 JSON/base64 协议 |
| 读取媒体 | `GET /{bucket}/{object}`；200 返回二进制 | 请求只访问部署配置选定的服务，不接受客户端提供任意 origin/bucket/object |
| 视频/音频定位 | GET 携带单段 Range，支持 `bytes=start-end`、`bytes=start-`、`bytes=-suffix` | 保留 206、Content-Range、Content-Length、Accept-Ranges；无法满足的范围保留 416；不把 Range 请求强制全量下载 |
| 物理删除、签名访问链接、直传凭据 | 当前 HTTP 未注册这些操作；对应 RPC 只在 gRPC API | 不调用猜测的 DELETE、GetAccessURL 或 GetUploadInfo HTTP 地址，不宣称有 24 小时签名链接或客户端限时直传 |

不显式指定 provider，交给 storage 的已有写入/读取路由；读操作不固定底层厂商。上游 HTTP 无鉴权，AFXEN 不附带用户 Cookie、CSRF、模型 Key 或伪造 Token。此边界采用已选外部 HTTP 契约，不改成另一套业务响应格式。

上传只有完整收到 200 且空响应才视为 OSS 保存完成。已核实上游部分错误可能是 HTTP 200 加 JSON 错误体，因此非空、JSON 错误、超时和中断不能记为成功；结果未知时不自动重传或覆盖。读取也必须识别 JSON 错误体，不把它当作媒体入库或显示。只按已验证媒体内容/已保存 MIME 提供响应：上游对 jpg 返回 image/png、对视频返回 application/octet-stream 的行为不能直接用作本项目真实格式判断。非预期状态、重定向或异常响应明确报错，不转发上游原始内部错误及地址到普通页面。

## 所有权与唯一来源

Server 为每份媒体分配不可变 ID 和对象键；对象前缀来自实例配置，用户及项目归属来自当前认证上下文，不采用客户端声明的用户 ID、文件名或磁盘路径作为权限依据。bucket、服务地址与存储厂商不由个人设置接口修改；普通用户只操作自己的媒体记录。

候选新增 SQL `mediaFiles` 记录：用户 ID、逻辑工作区/资产位置、媒体 ID、storageKind、bucket/object、已验证 MIME、字节数、内容摘要、revision 和业务状态。逻辑路径保留现有节点/画布的引用格式；SQL 中每一用户逻辑位置唯一，对象键不可变且不可覆盖。`local` 记录显式关联尚未迁移的旧文件；`oss` 记录以云对象为唯一媒体内容来源，不同时把本地副本当作第二份持久来源。精确字段、索引、外键与 CAS 纳入同版数据库合同与迁移，不把 object URL 写成稳定业务主键。

页面继续通过 Port 和现有文件/资产入口操作逻辑位置，生产适配层不直接请求无鉴权 OSS；Scenario 继续纯内存。素材上传、生成结果保存、历史、个人资产、项目/模板复制及引用都消费同一服务端媒体实现，不能只改资产上传按钮。画布/对话/JSON、可信插件、应用配置和临时处理文件不整体塞入 OSS，也不全局改写 `@toonflow/file`。

## 读取与模型引用

浏览器使用本项目同源媒体入口。Server 先验证会话与媒体归属，再代理 OSS；不把无鉴权的 OSS 地址直接作为浏览器公开预览地址，不把该地址缓存进画布/对话。Range、取消、连接关闭及资源释放在代理中保留；客户端断开及时停止上游读取，避免视频定位反复缓冲整个文件。

无鉴权 OSS 必须处于受控网络访问范围。若用户能绕过 AFXEN 直接访问它，AFXEN 的业务鉴权无法保护该地址上的文件；仅隐藏 URL 或增加对象前缀不构成个人隔离。平台不改变外部服务的鉴权设置，也不假装该网络条件已在目标机验证。

供应商参考素材继续由 Server 读取并按已接入适配器支持的字节/base64或供应商受控上传能力传递；不能把容器内网 URL 当作供应商可访问 URL。仅接受外部 HTTPS 链接的能力若缺少有效受控传输路径，明确提示并保留输入，不自动公开 OSS、不丢弃参考素材，也不为转换失败重提收费任务。

## 写入、复制及失败

沿用现有单文件 100 MiB 上限，来源分别为 `utils/assets/index.ts`、`utils/media/generation.ts` 和应用原始字节入口；不因云存储默认扩大上限。进入 OSS 前验证实际长度和媒体格式，运行时检查必须保留；生成文件先确认厂商真实结果，再保存，不能以示意素材替代。

先完成本次新对象上传，再以当前用户和 expectedRevision 事务发布媒体记录及业务关联。OSS 成功不等于业务保存完成；SQL 失败保留可恢复的上传结果与明确错误，不删除既有对象，不把未登记结果报为成功。事务与对象存储不具有跨系统原子性，不能用 SQL rollback 宣称云对象已回滚。补偿只处理能证明属于本次未发布操作的内容；当前 HTTP 无删除能力时登记待处理对象并交运维，不伪造清理成功。

更新采用新对象键和 SQL CAS 切换引用，不覆盖旧键。同名保护仍作用于用户逻辑位置；同用户过期 revision 仍返回409并保留草稿。复制项目/模板时，以已授权来源 GET 加新对象 POST 创建独立副本，全部文件/引用检查完成后才发布新项目；不能因缺少 Copy RPC 改为依赖源项目的可变对象。取消和中断说明实际已保存部分，不自动重试结果未知的上传或供应商任务。

## 删除提议与兼容停点

当前 HTTP 不支持物理删除，不能完整替代既有本地文件删除。首版候选建议：云媒体删除只移除所属用户的业务关联并标记逻辑删除，保留其它画布、对话和模板引用；真实对象由后续具备受控删除能力的运维流程清理。此项改变云媒体的物理回收时机，需随本版明确确认，批准前不将云适配接到现有删除入口。若要求立即物理删除，则必须取得真实 HTTP 删除契约后再完成该能力，不改外部仓库或擅自切换 gRPC。

旧媒体留在原卷，由显式 `local` 记录继续读取，不因启用 OSS 批量搬迁或删除。新媒体成功入云后只从云记录读取，云故障不能偷偷落回本地或显示保存成功。后续旧文件上云须独立列出来源、目标、摘要核对、逐项状态及失败恢复，取得实际目标和操作授权；本轮不操作用户数据。
